# 트러블슈팅

실제 개발 중 마주친 문제와 해결 과정.

## 1. Groq API → 로컬 LLM 완전 교체

### 문제
- Groq API 호출 시 자주 오류 발생
- 외부 의존, 비용 발생, 호출 제한
- 공공기관 면접에서 "외부 AI에 데이터 보내냐"는 질문 응대 어려움

### 해결
- `backend/.../service/ChatService.java` 전면 재작성
  - 엔드포인트를 Groq → `http://localhost:8001/api/agent/chat`로 교체
- `application.properties`에서 Groq 관련 설정 제거
  ```diff
  - grok.api.url=...
  - grok.api.model=...
  + agent.api.url=http://localhost:8001
  ```
- Python 에이전트(FastAPI + LangGraph + Ollama + MCP) 신규 구축

### 결과
- 외부 API 비용 0원
- 폐쇄망 환경 동작 가능

## 2. 포트 충돌 (8000 → 8001)

### 문제
```
address already in use: 0.0.0.0:8000
```
- 다른 프로젝트가 8000 사용 중

### 해결
- `agent_server.py` 마지막 줄 변경:
  ```python
  uvicorn.run(app, host="0.0.0.0", port=8001)
  ```
- `application.properties`도 함께 수정:
  ```properties
  agent.api.url=http://localhost:8001
  ```

### 포트 죽이는 명령
```bash
lsof -i :8000        # 8000 쓰는 프로세스 PID 확인
kill -9 [PID]
```

## 3. mvnw 권한 오류 (Mac)

## 4. Python 가상환경 문제

### 문제 1: `externally-managed-environment`
```bash
$ pip install fastapi
error: externally-managed-environment
```
Homebrew Python은 시스템 전역 설치를 막음.

### 해결
```bash
python3.14 -m venv ai-env
source ai-env/bin/activate
pip install fastapi   # 가상환경 안에서 OK
```

### 문제 2: VSCode에서 import 오류
- IDE가 시스템 Python (3.14)을 인터프리터로 잡음 → fastapi 못 찾음

### 해결
- VSCode 우하단 Python 버전 클릭 → `ai-env/bin/python` 선택
- 또는 `.vscode/settings.json`에 추가:
  ```json
  { "python.defaultInterpreterPath": "${workspaceFolder}/ai-env/bin/python" }
  ```

## 7. MultiServerMCPClient 컨텍스트 매니저 오류

### 문제
```python
async with mcp_client:
    tools = await mcp_client.get_tools()
```
- `langchain-mcp-adapters 0.2.2`에서 context manager 지원 제거됨
- `AttributeError` 발생

### 해결
```python
mcp_client = MultiServerMCPClient({...})
tools = await mcp_client.get_tools()   # 직접 호출
```

## 8. `asyncio.to_thread`로 async 도구 호출 실패

### 문제
```python
result = await asyncio.to_thread(agent.invoke, {...})
# NotImplementedError: StructuredTool does not support sync invocation
```
- MCP 도구는 async인데 `agent.invoke`는 sync → 호환 안 됨

### 해결
```python
result = await agent.ainvoke({...})  # ainvoke 사용
```

## 9. `<think>` 태그로 인한 빈 응답

### 문제
- 사용자 응답에 `<think>...</think>` 블록만 있고 그 뒤가 비어 있음
- `extract_answer`가 "응답을 생성할 수 없습니다" 반환

### 원인
- qwen3 thinking 모드가 모든 토큰을 think 안에 소진
- `num_predict=512`가 부족

### 해결
- `num_predict=2048`로 증가
- `extract_answer` 보완:
  ```python
  if "<think>" in content:
      after = content.split("</think>")[-1].strip()
      if after: return after
      # think 블록 안 내용이라도 반환
      inside = content.split("<think>", 1)[-1].split("</think>")[0].strip()
      if inside: return inside
  ```

## 10. CORS + 더블 슬래시 URL

### 문제
- 프론트에서 `http://localhost:8080//api/chat` 호출 → 404

### 원인
- `.env`의 `VITE_API_URL=http://localhost:8080/` (뒤에 `/` 있음)
- 코드: `${API_BASE}/api/chat` → 더블 슬래시

### 해결
- `.env` 수정:
  ```
  VITE_API_URL=http://localhost:8080
  ```

## 14. 챗봇 응답 정확도 문제 (현재 진행 중)

### 문제
- "가장 막히는 교차로 3곳" 질문 시 엉뚱한 교차로 응답
- 사이드바엔 여의도역 5km/h인데 AI는 다른 교차로 뽑음

### 원인
- `/api/signals` 응답에 `speed` 필드 없음 (신호 데이터만 있음)
- MCP `get_bottleneck_list`가 잘못된 데이터를 정렬

### 해결 (진행 중)
- `mcp_server.py`에서 속도 0 이하 제외:
  ```python
  valid = [s for s in signals if spd(s) > 0]
  ```
- 근본 원인: `TrafficStatus`에 `speed` 필드 추가 필요
- 또는 별도 엔드포인트 `/api/bottlenecks`로 사전 계산해서 노출

## 15. 컴퓨터 발열 / GPU 100%

### 증상
- 챗봇 사용 시 GPU 100%, RAM 85%
- 맥북 발열

### 원인
- qwen3:30b-a3b는 30B 모델 (활성 3B여도 메모리 18GB+)
- 추론 시 GPU 풀로 사용 정상

### 대응
- 모델 작게 (qwen3:7b 또는 qwen3:4b로 교체 가능)
- 챗봇 미사용 시 Ollama 종료:
  ```bash
  pkill -f ollama
  ```
- 또는 모델 메모리에서 해제:
  ```bash
  curl -X POST http://localhost:11434/api/generate \
    -d '{"model":"qwen3:30b-a3b","keep_alive":0}'
  ```
