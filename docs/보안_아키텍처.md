# 보안 아키텍처

## 1. 폐쇄망 대응 설계

### 핵심 원칙
**모든 AI 처리는 로컬에서 완결**. 외부 AI API 호출 없음.

### 외부 의존성 제거 내역

| 이전 | 이후 |
|---|---|
| Groq API (외부) | Ollama qwen3:30b-a3b (로컬) |
| OpenAI API (사용 안 함) | LangChain + LangGraph (로컬) |
| Pinecone (사용 안 함) | (RAG는 향후 ChromaDB 로컬 구축 예정) |

### 망분리 환경 동작 검증
- 인터넷 차단 환경에서도 Spring Boot + Ollama + React 정상 동작
- 단, 다음만 외부 연결 필요:
  - V2X 공공 API (실제 운영 시) — `apis.data.go.kr`
  - Kakao Maps SDK — 폐쇄망에서는 미터 타일 자체 호스팅 필요

## 2. 로컬 LLM 보안

### Ollama 로컬 실행
- 모델: `qwen3:30b-a3b` (~18GB 디스크)
- 포트: `localhost:11434` (외부 노출 없음)
- 데이터: 모든 추론 메모리 내, 외부 전송 0
- 사용자 질의 내용이 외부 서버로 가지 않음 → **개인정보·기밀 안전**

### 모델 출처
- Qwen3는 Alibaba가 공개한 오픈 가중치 모델 (Apache 2.0)
- 로컬 다운로드 후 인터넷 차단 가능

## 3. Oracle Wallet 보안

### Wallet 인증의 장점
- 사용자명/비밀번호만으로는 접속 불가
- mTLS 인증 + 키 파일 + 비밀번호 조합
- IP allowlist 추가 적용 가능

### 파일 관리
- `.gitignore` 처리:
  ```
  backend/src/main/resources/wallet/
  ```
- 팀원 간 별도 안전 경로(Slack DM, 사내 NAS 등)로 공유

### TNS_ADMIN 경로
- 운영 환경: 절대 경로 권장 (`/opt/oracle/wallet/`)
- 개발 환경: 프로젝트 내 상대 경로 (`src/main/resources/wallet/`)

## 4. 환경변수/시크릿 관리

### application-secret.properties (gitignore)
포함 내용:
- Oracle DB URL/사용자/비밀번호
- V2X 공공 API 키
- Kakao API 키
- 신호 시뮬레이션 API 키

### frontend/.env (gitignore)
포함 내용:
- `VITE_KAKAO_APP_KEY`
- `VITE_UTIC_KEY`
- `VITE_VWORLD_API_KEY`

⚠️ `VITE_*` 접두 환경변수는 빌드 시 번들에 포함됨 → 클라이언트 노출됨.
민감 키는 백엔드에서만 사용.

## 5. CORS 정책

### 백엔드 CORS
```java
@CrossOrigin(origins = "http://localhost:5173")
```
- 로컬 개발 환경에서만 React 도메인 허용
- 운영 시: 정확한 도메인으로 제한

### 에이전트 CORS
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", "http://localhost:8080"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 6. WebSocket 보안

### 현재 (개발)
- 인증 없음 (`ws://localhost:8080/ws/traffic` 누구나 연결 가능)
- 로컬 개발 한정

### 운영 시 권장
- WSS (TLS) 적용
- 연결 시 JWT 토큰 검증
- IP 화이트리스트

## 7. 공공 인프라 데이터 보호

### V2X 데이터의 민감도
- 교차로 신호 상태 (제3자가 알면 신호 위반/사고 유도 가능)
- 차량 평균 속도 (도시 운영 정보)
- CCTV 위치 (보안 관점에서 민감)

### 보호 조치
- 모든 데이터는 로컬 캐시에만 보관 (외부 전송 없음)
- AI 추론도 로컬에서 처리
- 외부 LLM에 V2X 데이터 절대 전송 안 함

## 8. SQL Injection 방지

- JPA 사용 (자동 Prepared Statement)
- `@Query` 사용 시 파라미터 바인딩 (`?1`, `:param`)
- 사용자 입력 직접 SQL 조립 금지
- 동적 쿼리는 `Specification` / `Criteria API`

## 9. 입력 검증

### 백엔드
- `@Valid` + Bean Validation
- `@RequestParam` / `@RequestBody`에 타입 강제
- 예외는 `ControllerAdvice`로 통합 처리

### 에이전트
- Pydantic 모델로 요청 본문 검증
- `ChatRequest`, `DistrictRequest` 등 정의됨

## 10. 공기업·공공기관 면접 셀링 포인트

### 핵심 메시지
> "본 시스템은 외부 AI API에 단 한 줄의 데이터도 보내지 않습니다.
> 모든 추론은 로컬 LLM(qwen3:30b-a3b)으로 처리되며,
> 망분리 환경의 공공·관제 인프라에 그대로 배포 가능합니다."

### 비교
| 항목 | 외부 API 방식 | 로컬 LLM 방식 |
|---|---|---|
| 데이터 외부 전송 | O (위반) | X (안전) |
| 망분리 환경 | 불가 | 가능 |
| 비용 | 호출당 과금 | 0원 (전기료만) |
| 응답 속도 | 네트워크 의존 | GPU 의존 (수초) |
| 장애 시 | 외부 장애 영향 | 자체 통제 |

### 추가 강점
- **MCP 표준 채택**: 안드로픽이 만든 표준 프로토콜 → 향후 확장성
- **Human-in-the-loop**: AI가 결정하지 않고 권고만 → 책임 소재 명확
- **감사 추적**: 모든 도구 호출이 LangGraph 메시지로 로깅 → 사후 검증 가능
