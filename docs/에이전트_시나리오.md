# 에이전트 시나리오

## 시나리오 1: 우천 정체 신호 연장 권고

### 상황
- 강남구 일부 교차로에 비 감지
- 평균 속도 12km/h로 지속 (10분 이상)
- 출퇴근 시간 (오후 6시)

### ReAct 루프

#### 1회차: 데이터 조회
```
Observe: 사용자 "강남구 막히는 곳 어디야?"
Think: get_district_traffic 도구로 조회 필요
Act: get_district_traffic("강남구")
```

**도구 결과**:
```json
{
  "district": "강남구",
  "total_crossroads": 47,
  "avg_speed_kmh": 18.5,
  "top3_congested": [
    {"name": "강남역사거리", "speed_kmh": 12},
    {"name": "역삼역사거리", "speed_kmh": 14},
    {"name": "신논현역", "speed_kmh": 16}
  ]
}
```

#### 2회차: 컨텍스트 보강
```
Observe: 상위 3곳이 모두 15km/h 이하
Think: 가장 심한 강남역의 상세 데이터 확인
Act: get_traffic_data("1234")  // 강남역 ID
```

**도구 결과**:
```json
{
  "weather": "비",
  "speed": 12,
  "riskScore": 78,
  "phase_cycle": 60
}
```

#### 3회차: 최종 응답 생성
```
Observe: 비 + 저속 + 위험도 78점
Think: 신호 +15초 연장 권고
Act: (도구 호출 없이 최종 응답)
```

**AI 응답**:
> 강남구 현재 평균 18.5km/h로 서행 중입니다.
> - 강남역사거리: 12km/h (위험도 78점, 비)
> - 역삼역사거리: 14km/h
> - 신논현역: 16km/h
> 
> 강남역 신호 주기를 60초 → 75초로 +15초 연장 권고합니다.
> 우천 시 안전거리 확보와 차량 처리량 증가에 효과가 있습니다.

## 시나리오 2: 단일 교차로 질문

### 사용자 입력
"잠실역 교차로 어때?" (교차로 선택 안 함)

### ReAct 루프

#### 1회차: 이름 검색
```
Act: search_crossroad_by_name("잠실")
→ [{ crsrdId: "1007", crsrdNm: "잠실역사거리" }]
```

#### 2회차: 상세 데이터
```
Act: get_traffic_data("1007")
→ { speed: 35, weather: "맑음", riskScore: 42 }
```

#### 3회차: 응답
> 잠실역사거리는 현재 35km/h로 서행 중이며, 위험도 42점(주의)입니다.
> 날씨 맑음, 신호 조정 불필요. 모니터링만 권장.

## 시나리오 3: Human-in-the-loop 승인 필요

### 상황
- 에이전트가 신호 +30초(50% 증가) 권고
- 변경 폭이 30% 초과 → 자동 적용 불가

### 흐름
```
1. AI 권고: "강남역 신호 60초 → 90초 (+50%)"
2. 시스템: "30% 초과 변경, 관제사 승인 필요"
3. 관제사: SimulationDashboard로 결과 확인
4. 승인 → set_signal_timing 도구 실제 호출
5. 거부 → 권고 무시
```

## ReAct 루프 단계 요약

| 단계 | 역할 | 도구 호출 |
|---|---|---|
| 1회차 | 데이터 조회 | get_district_traffic / search_crossroad_by_name |
| 2회차 | 컨텍스트 보강 | get_traffic_data |
| 3회차 | (필요 시) 추가 조회 | get_bottleneck_list |
| 최종 | 자연어 응답 생성 | (도구 호출 없음) |

평균 도구 호출 횟수: 1~3회.
4회 초과 시 LangGraph 기본 recursion limit (25) 내에서 자동 종료.

## Human-in-the-loop 정책

### 자동 적용 (관제사 승인 없이 즉시 반영)
- 신호 변경 폭 ±5초 이내
- 위험도 50점 미만
- 평일 심야 (저트래픽)

### 승인 필요
- 신호 변경 폭 ±5초 초과
- 위험도 70점 이상
- 출퇴근 시간대 (07~10시, 18~20시)
- 비/눈 상황

### 강제 차단 (자동 거부)
- 신호 주기 30초 미만 또는 180초 초과 (도로교통법 위반)
- 보행 신호 미설정
- 인접 교차로 동기화 시뮬레이션 미수행

## 시나리오 4: 시뮬레이션 미리보기

### 흐름
```
1. 관제사: "강남역 신호를 90초로 바꾸면 어떻게 돼?"
2. AI:
   - 현재 데이터 조회 (get_traffic_data)
   - 가상 시나리오 계산
   - "예상: 대기시간 +12초, 처리량 +18%, 위험도 -8점"
3. 관제사: 시뮬레이션 결과 확인 후 승인/거부
```

## 시나리오 5: 다중 교차로 동시 분석

### 사용자 입력
"송파구에서 가장 위험한 5곳 분석해줘"

### ReAct
```
1. get_district_traffic("송파구")
2. 각 교차로마다 get_traffic_data 호출 (5회)
   ⚠️ 호출 많아짐 → 응답 시간 30~60초
3. 종합 응답
```

→ **성능 개선 여지**: 백엔드에 "구별 위험 TOP N" 단일 엔드포인트 추가하면 1회 호출로 끝남.

## 에이전트가 잘 답하는 질문 유형

✅ "잠실역 어때?"
✅ "지금 가장 막히는 곳 3개 알려줘"
✅ "강남구 평균 속도는?"
✅ "비 오는데 신호 어떻게 바꿔야 해?"

## 에이전트가 어려워하는 질문 유형

❌ "어제 대비 오늘은?" (시계열 메모리 없음)
❌ "이 교차로 1년 사고 이력은?" (외부 DB 미연동)
❌ "전체 서울 모든 교차로 분석" (데이터량 과다, 컨텍스트 폭발)
